# 材质跨项目使用与渲染外观约定

版本：`shadow-pbr-appearance-v1`，2026-10-24。

## 目标与边界

目标是在游戏、网页或其他项目中保留本库资产的颜色关系、粗糙程度、金属/非金属特征和低多边形表面风格，**不要求复制缩略图的灯位、相机或展示棚**。

实现方式是“每件资产自己的材质 + 全项目统一的渲染解释规则”，不是把所有资产套上同一个材质。机器可读说明：[material-appearance-v1.json](../config/material-appearance-v1.json)。它是接入约定，不会自动更改 GLB、现有生成脚本或网页预览器。

光照仍是材质外观的一部分。颜色鲜艳的环境会染色，没有反射环境的金属会偏暗，不同明暗分布会改变高光和粗糙度的视觉感受。统一渲染规则能减少差异，但不能保证任意引擎、任意灯光下与离线图像完全相同。

## 哪些参数属于每件资产

以该资产 `model.glb` 的材质定义为准，保留：

- 基础颜色、基础色贴图及各子网格的材质绑定。
- 金属度、粗糙度及对应贴图。
- 法线、切线、UV、法线贴图；不要擅自把原低多边形面全部平滑。
- 遮蔽、发光、透明模式、双面设置，以及文件实际使用且目标引擎支持的材质扩展。

正常 glTF 加载器会读取这些值，不需要人工给每个模型重新设置一遍。不要全局强制统一 `roughness`、`metallic` 或颜色，也不要因材质名称含“铜”“玻璃”就自行改成金属或透明：有些资产是明确的风格化不透明表现。

没有贴图不等于材质丢失。当前抽样六件都是由数值颜色、金属度和粗糙度定义的材质，GLB 中没有图片贴图，也仍然有完整的这类 PBR 材质信息。

## 哪些规则可以统一

1. 使用兼容 glTF 2.0 metallic-roughness 的 PBR 渲染，保留 GLB 导入材质；不要换成无光照基础材质。
2. 在线性色彩空间中计算光照。一般 SDR 输出采用 sRGB。
3. 基础色/发光贴图按 sRGB 解释；法线、金属度、粗糙度、遮蔽是非颜色数据。GLB 的数值 `baseColorFactor` 已属于线性因子，不能再错误地做一次 sRGB 转换。
4. 当前抽查的缩略图使用 AgX。目标渲染器支持时，可从 AgX 与中性曝光开始校准；不支持时选合适的显示变换进行一次项目级对照，不要声称 ACES、AgX 或其他实现完全相同。
5. 建议起点为 0 EV；Three.js 的曝光倍率起点为 1。它们是接入建议，不代表所有历史资产都已逐件核实使用完全相同的曝光、Look 或版本。
6. 项目提供适当的漫反射光和反射环境。校准材质时用中性环境，生产场景可按自身需求布光；不硬性固定灯数、灯位和相机。
7. 需要接近缩略图的层次感时，可使用适量接触阴影、阴影或 AO。不要将大幅加深 AO 当作修复材质；也不要重复叠加色调映射、增饱和、增对比滤镜。

**采样数不是材质参数。** Cycles 128 次采样影响离线噪声与耗时，并不能直接转换成实时引擎的“同质感开关”。相机焦距、构图、背景、接影地面也不属于资产本身的 PBR 材质。

## Three.js 接入示意

以下只表达项目级显示设置，不创建灯光、不覆盖资产材质，也不保证单凭这三行复刻 Blender：

```js
renderer.outputColorSpace = THREE.SRGBColorSpace;
renderer.toneMapping = THREE.AgXToneMapping; // 使用支持此常量的版本
renderer.toneMappingExposure = 1;            // 接入校准起点
// 使用 GLTFLoader 导入并保留材质；由项目提供合适的灯光/反射环境。
// 若使用后处理，确保输出变换只执行一次。
```

采用其他引擎时按对应 PBR/色彩管理选项映射，不照搬 Three.js 的灯光强度数值。首次接入选少量不同粗糙度与材质类型的代表资产校准，之后复用项目设置；不逐件重新出图验收。

## 已知网页预览与缩略图差异

对网页仓 `viewer.mjs` 的实际版本（blob `b600c355a271bb4afc681b65f20e462da9b69e4a`）读取发现：网页使用 sRGB 输出、ACESFilmic、38°透视相机、半球光及一盏方向光；没有设置环境贴图、启用阴影贴图或增加接影地面。

近期抽样生成源码使用 Cycles、AgX、正交相机、三盏面积灯和接影地面，且不同制作路径的灯光功率、位置、地面颜色并不完全相同。因此当前网页不是“缩略图等效渲染模式”。本次仅保存说明与配置，不改网页运行代码，不宣称已完成跨引擎视觉一致性验收。

## 历史参数是否还在

第一批只抽样六件，不全库扫描或重渲染：第一卷的背包、双人沙发、讲台；第二卷的骆驼、板球拍、夹台棱镜绘图器。

- 六件实际 GLB 均解析到了各自 PBR 材质。
- 六件 GLB 和生成源码的 SHA-256 均与目录记录一致。
- 三件第一卷样本在原不可变提交下仍能读取生成源码和 GLB；目录同时保留原生 blend 文件条目。近期三件读取已交付的本地原文件并核对同样的目录哈希。
- 本批只核原生文件存在，没有重新启动 Blender 打开全部原生文件，也没有重做图片或逐件验证全库。
- **早期某些脚本先保存 source.blend，之后才加入缩略图灯光和相机。** 因此不能保证每个旧 blend 都包含完整展示棚；相关构造与渲染设置仍可在已核实的生成源码中找到。材质与展示棚应分开判断。

具体样本、不可变提交链接、材质数值及验证范围：[第一批抽样记录](material-sampling-2026-10-24.json)。该结论只代表这些样本，不是“1000 多件全部复核通过”。

## 后续轻量维护

- 每件继续交付原五个核心文件；材质数值仍跟随 GLB/源码，不另要求人工维护一套重复的逐资产材质表。
- 共用规则更新在本配置中记录版本；确有特殊材质扩展、渲染器限制或非可移植效果时，在该件元数据/简短交付说明中注明。
- 后续按不同年代、制作路径和材质类型分批抽样。发现真实参数缺失才修对应资产或共用导出工具，不扩大为全库返工，不恢复互审关卡。
- 如需复刻某件原图，用其生成源码、对应 blend 和实际版本设置恢复展示场景；如只需在新场景使用其材质，优先直接加载 GLB 并遵循上述公共规则。
